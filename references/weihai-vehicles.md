# weihai vehicles — 查询线路车辆实时位置

对应 CLI 子命令:`weihai vehicles [<routeId>|--name <线路>] [选项]`

## input

| 参数 | 位置/选项 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `route_id` | 位置参数 | 二选一 | — | 数字 routeId |
| `--name <线路>` | 选项 | 二选一 | — | 按线路名定位(自动取第一个方向的 routeId) |
| `--json` | 选项 | | `false` | 输出结构化 JSON |
| `--city` | 选项 | | `371000` | 城市码或 type 值 |
| `--platform` | 选项 | | `2` | h5Platform,免授权直连 |
| `--timeout` | 选项 | | `10.0` | 请求超时秒数 |

`route_id` 与 `--name` 必须提供其一,且**互斥**。都缺 → `weihai vehicles` 报错退出码 2。

## action

命中:拿到一个 routeId(来自 `routes`)或线路名,想知道该线路**当前在跑的车辆**、完整经停站点序列与站点到站车辆数。

标准用法:

```bash
weihai vehicles --name 1路
weihai vehicles 3710000100128319 --json
```

## output

人读模式按顺序列出每个经停站点与车辆数:

```
1路  (江家寨立交桥 -> 实验中学)
    1. 江家寨立交桥
    2. 江家寨
    3. 海马地毯   [2车]
    4. 宋家洼
   ...
末/途经站点预报: 实验中学  ...
```

`--json` 返回单个 {route, nextBuses:{...}, stops:[...]}。`stops` 每项是 `{route_stop:{seq_no,stop_id,stop_name,lat,lng,...}, buses:[...]}`,`buses` 为该站即将到达的车辆数组(非运营时段为空)。

### 运营状态提示

当整条线路**无在线车辆**时,CLI 会按该线的首/末班时间与当前时刻自动补一行与官方 App 一致的文案:

- 当前未到首班 → `状态: 非车辆运营时间（06:00 发车）`
- 已过末班 → `状态: 非车辆运营时间（已过末班）`

这是 CLI 本地根据 `first_bus`/`last_bus` 推断的,不是接口返回的 `no_bus_desc`(该字段常为空)。
`--json` 模式不加这行(由调用方自行判断)。

## side_effect

- 只读,无副作用
- 输出反映**查询瞬间**的实时状态,不要保存为长期静态数据
- 夜间/非运营:车辆数组为空、车辆数与到站预报为空,属正常

## 失败处理

- 未提供 routeId 或 --name → 退出码 2
- 该线路无实时数据 → 输出 `(该线路实时数据不可用)`,退出码 1
- 网络/服务端错误 → 非零退出码 + 错误信息
